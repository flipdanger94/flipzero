## Уточнение первоначального аудита

Пропуск XP-backfill в build был намеренным: docs/voice-xp-overhaul.md запрещает автоматическое выполнение этой операции. Ошибка процесса состояла в отсутствии проверки готовности схемы. Исправление сохраняет ручной rollout XP и добавляет понятный отказ сборки. Автоматический пересчёт XP не добавлен.

## Миграция 0034

Добавляет media_assets.attached_at, media_attachment_links, индексы и журнал app_schema_migrations.
Старые вложения сообщений получают контекст и владельца; текущие аватары/баннеры сохраняют публичный доступ; sound assets проверяют членство сообщества. Повреждённые DM-envelope не блокируют миграцию.

Ссылки вложений переписываются с /api/v1/media/{id} на /api/v1/attachments/{id}. Новый namespace предотвращает использование старых публично закэшированных ответов внутри приложения. При выпуске следует также инвалидировать прежний CDN-кэш /api/v1/media/* и /_next/image, чтобы ранее распространённые ссылки не обслуживались из старого кэша. Уже скачанные третьими лицами копии отозвать невозможно.

Миграция выполняется в транзакции под advisory lock и записывается в журнал. Повторная сборка не повторяет backfill вложений. Журнал включён в Drizzle-схему.

Квоты — выбранные технические ограничения, их можно скорректировать после оценки объёма реальных данных. Пользователи, уже превышающие квоту, сохраняют доступ к существующим вложениям; новые загрузки будут отклонены.

## Проверка и выпуск

Добавлены интеграционные тесты на встроенном PostgreSQL-движке PGlite: реальные SQL-запросы и обработчики HTTP с подставленной текущей сессией. Проверены приватные файлы, ReadHistory, блокировки, удаление сообщений, ownership/метаданные, квоты, гонки accept и attendance, бан токенов, миграция старых envelope и журнал однократного применения.

Отдельные тесты проверяют webhook network boundary, readiness и HTML приватных изображений.
PGlite сериализует транзакции одного подключения; распределённые блокировки между несколькими настоящими PostgreSQL-подключениями нужно дополнительно проверить на staging.

Полный npm/pnpm build с deployment-миграциями требует DATABASE_URL. Локально проверяется next build --webpack; SQL миграции 0034 проверяется интеграционными тестами.

Перед выпуском:

1. Снимок целевой базы; изолированная preview-БД с готовой XP-схемой.
2. Preview build, миграция 0034 и проверка записи в журнале.
3. Два аккаунта: сообщения/вложения/отзыв прав; клановый polling после потери сети.
4. Реальные звонки и screen share; мобильные размеры 360/390 px.
5. Инвалидация старого CDN-кэша при production release.

В рамках исправлений production-БД и main не изменялись.
