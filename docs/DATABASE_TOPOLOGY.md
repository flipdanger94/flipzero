# Database topology

FlipZero остаётся в безопасном single-primary режиме, пока не настроены дополнительные базы. Маршрутизатор использует rendezvous hashing по `spaceId`, поэтому добавление шарда перемещает минимально возможную долю сообществ.

## Конфигурация

`DATABASE_URL` всегда остаётся основной и резервной базой. Дополнительные шарды задаются секретной переменной `DATABASE_SHARDS_JSON`:

```json
[
  { "id": "eu-1", "regions": ["fra1", "arn1"], "databaseUrl": "postgresql://..." },
  { "id": "us-1", "regions": ["iad1", "sfo1"], "databaseUrl": "postgresql://..." }
]
```

URL подключений никогда не возвращаются из health API. До переноса глобальных пользователей, membership-проекций и внешних ключей production должен работать без `DATABASE_SHARDS_JSON`.

Таблица `space_placements` является глобальным routing-каталогом. Она хранит закреплённый шард, домашний регион, состояние миграции и версию маршрута. При развёртывании существующие сообщества автоматически и идемпотентно закрепляются за `primary`; новые получают placement в той же транзакции, что и само сообщество.

`getDatabaseForSpace()` читает закреплённый placement из primary-каталога. Для `primary` он возвращает существующее подключение. Для отдельного шарда подключение разрешается только при состоянии `active` и наличии соответствующей конфигурации; иначе запрос останавливается явной ошибкой, предотвращая split-brain и случайную запись не в ту базу.

## Порядок включения

1. Создать шарды и применить все Drizzle-миграции.
2. Реплицировать глобальные таблицы `users`, `sessions` и routing-каталог `space_placements`.
3. Перенести одно тестовое сообщество и проверить права, сообщения, модерацию и откат.
4. Включить dual-write и сверку данных.
5. Переключить чтение, затем запись; после окна наблюдения отключить dual-write.
