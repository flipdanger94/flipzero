# UI/UX магазина, профилей и проверка стрима

Работа выполнена в одном чате по приложенному ТЗ. Исходный коммит — `d8e020f`; перед завершением включены изменения `main` до `50bd863`, в том числе новый UI демонстрации экрана в личных звонках. История других чатов не использовалась.

## Этапы и изменения

1. **Основа.** `app/design-system.css` содержит шкалы отступов, радиусов, типографики и семантические цвета. `components/ui/dialog.tsx` задаёт общую оболочку, а `use-modal-a11y` управляет стеком окон, Escape, удержанием/возвратом фокуса и блокировкой прокрутки. Вложенный диалог обрабатывает клавиши первым.
2. **Магазин.** `components/economy/` содержит StoreTab, InventoryTab, QuestsTab, HistoryTab, ItemCard и Currency. Один ItemCard применяется в каталоге, подборке, инвентаре и превью. До двух статусных меток; редкость передаётся текстом без дополнительной цветной рамки. Доступность показывается конкретным сроком с датой и временем. Признаки анимации/набора раскрываются в превью. `priceMoneyCents` убран из публичного ответа магазина, но сохранён в БД для совместимости. Покупки/экипировка не меняют серверные правила списания средств.
3. **Профили.** Добавлен `/users/[userId]` и ссылка из мини-профиля. Маршрут требует входа, данные получает существующий API с проверками приватности и блокировок. Из страницы можно открыть DM через `/app?dm=...`. Меню, форма жалобы и операции безопасности выделены в отдельные модули. Уровень/XP/статус и визитка сохранены: в актуальном коде они уже существовали, вопреки отдельным пунктам исходного аудита.
4. **Диалоги.** Общий Dialog используется для магазина, полного профиля, жалоб и подтверждений, Discovery, Wiki, Events, Social Hub, админки и вложенных форм выдачи, кабинета разработчика, поиска, историй, редактора изображения, настроек аккаунта/сообщества, управления каналами, категориями, ролями, участниками, приглашениями, модерацией, прогрессом, состоянием системы и личным звонком. Специализированные немодальные меню устройств, уведомления/входящий звонок и пошаговый onboarding не переделывались в блокирующие полноэкранные окна. Неиспользуемый legacy ProfileModal в persistent-chat также не заменялся.
5. **CSS.** Глобальные CSS подключаются только прямыми импортами в `app/layout.tsx`. В globals.css остаётся лишь импорт самого Tailwind. Порядок существующих слоёв сохранён; три соседних файла Discovery/Events/Wiki объединены в читаемый `community-dialogs.css`. С учётом нового design-system количество глобальных CSS-файлов уменьшилось на один. Новые общие правила подключаются последними, поверх legacy-слоёв; полное удаление всех legacy-тем не проводилось.
6. **QA.** Локальные браузерные проверки на 360, 390, 768 и 1440 px проведены на реальных компонентах с подменой ответов API. Проверены каталог/инвентарь, превью, мини- и полный профиль, Discovery, Events и Wiki. Горизонтального переполнения страницы и диалогов нет; максимум две метки; фокус внутри модалки и возврат на кнопку подтверждены. Escape и клик по крестику проверены. Скриншоты позволили найти и исправить перекрытие имени аватаром, скрытый крестик превью и обрезание Discovery. Лендинг также открывался в браузере. Это не проверка реальных покупок или записей в БД.

## Стрим: найдено и исправлено

- При переключении между авторами оставались подписки на экран/звук предыдущего стрима. Теперь активен только выбранный поток; при выходе из просмотра обе подписки снимаются.
- Регулятор звука стрима затрагивал микрофон автора. Аудиоэлементы теперь различают microphone/screen; stream mute/volume не меняют голос. Общая громкость и deafen продолжают действовать на оба источника.
- Поздно пришедший аудиотрек теперь сразу получает текущие mute/volume.
- Остановка демонстрации кнопкой браузера синхронизирует локальный статус и серверный streaming-флаг через события публикации/снятия трека.
- Удаление только ScreenShareAudio не закрывает продолжающееся видео.
- Уход автора/разрыв соединения очищает выбранный стрим. При возврате из фокусного режима камеры прикрепляются к вновь появившимся элементам.
- Повторное нажатие во время выбора экрана заблокировано; после ухода из комнаты незавершённый запуск останавливается.
- **Личные звонки из нового main:** токены звонящего и принимающего не разрешали SCREEN_SHARE/SCREEN_SHARE_AUDIO, хотя кнопка стрима уже была добавлена. Общая функция разрешений добавляет эти источники для обоих участников, сохраняя запрет камеры в аудиозвонке. Исправлены размеры экрана, полноэкранное отображение, очистка состояния и защита от повторного запуска. Локальное видео без звука, чтобы не создавать самопрослушивание.

## Проверки и ограничения

- `pnpm exec next build --webpack` завершился успешно, включая TypeScript, генерацию страниц и build traces. Обёртка `pnpm build` с миграциями БД не запускалась: DATABASE_URL отсутствует.
- Новые тесты проверяют переключение подписок, разделение звука, deafen, обработку локального списка игнора/ошибок блокировки, отправку жалобы и содержимое подписанного JWT с разрешениями стрима.
- Полный Vitest: **174 passed, 2 failed**. Два сбоя воспроизводились на исходном коммите без правок: `clans-system.test.ts` ожидает `variant="full"` в старом файле, хотя рендер уже вынесен в FullUserProfile; `persistent-layout.test.ts` ожидает старую строку CSS dock. Новые сбои от переноса/форматирования файлов устранены обновлением путей и проверок пробелов в source-contract тестах.
- Проверенные новые модули проходят ESLint без ошибок и предупреждений.
- В окружении нет DATABASE_URL, LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET. Миграции и реальные пользовательские операции не запускались. Сквозная передача видео/звука между двумя авторизованными клиентами через LiveKit **не подтверждена**.
- Временный QA-маршрут с фикстурами удалён перед production-сборкой.
- Изменения схемы БД и миграции не требуются.

## Обязательный оставшийся LiveKit smoke-test перед выпуском

Два тестовых аккаунта: войти в серверный и клановый войс, затем выполнить личный звонок. Проверить демонстрацию вкладки/окна/экрана, системный звук там, где он поддерживается браузером, переключение между двумя авторами, mute/volume стрима отдельно от голоса, deafen, остановку средствами браузера, повторный запуск, уход автора, восстановление сети и завершение звонка. Проверить отсутствие оставшихся аудиотреков после закрытия просмотра. Повторить для звонящего и принимающего. Реальная поддержка системного звука зависит от браузера, ОС и выбранного источника.

Результаты браузера и два примера экранов находятся в `docs/qa/ui-stream-2026-09-27/`.
